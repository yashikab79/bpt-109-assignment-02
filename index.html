1. Functional components of the CPU and types of main memory

Question. List the three main functional components of the CPU and identify four types of main memory (RAM, ROM, cache memory and registers), stating one key characteristic of each.

Three main functional components of the CPU

  1. Control Unit (CU): Directs and coordinates computer operations. It fetches instructions from memory, decodes them and issues control signals to the other components.
  2. Arithmetic Logic Unit (ALU): Performs arithmetic operations such as addition and subtraction, and logical operations such as AND, OR, NOT and comparisons.
  3. Registers: Very small, high-speed storage locations inside the CPU that temporarily hold instructions, addresses and data currently being processed.

Four types of main memory

Types of memory and their key characteristics
Memory typeKey characteristicMain purpose
RAM (Random Access Memory)Volatile: its contents are lost when power is switched off.Temporarily stores programs and data currently in use.
ROM (Read Only Memory)Non-volatile: it retains its contents without power.Stores firmware and essential startup instructions.
Cache memorySmall, very fast memory located close to or inside the CPU.Keeps frequently or recently used instructions and data ready for the processor.
RegistersFastest storage locations, built directly into the CPU.Hold immediate values, addresses and instructions during execution.

Conclusion: The CU controls operations, the ALU processes data and registers provide immediate storage. RAM, ROM, cache and registers serve different roles in making instruction processing efficient.

2. Fetch–decode–execute instruction cycle

Question. Explain the fetch–decode–execute instruction cycle, detailing how the control unit, ALU and CPU registers (PC, IR, MAR, MDR, accumulator) interact with main memory while a program instruction is processed.

The fetch–decode–execute cycle is the repeated sequence through which the CPU processes program instructions. The control unit coordinates the cycle, the registers hold the required information and the ALU performs arithmetic or logical work.

Important CPU registers

Registers involved in instruction processing
RegisterFunction
Program Counter (PC)Stores the address of the next instruction to be fetched.
Instruction Register (IR)Holds the current instruction while it is decoded and executed.
Memory Address Register (MAR)Holds the address of the memory location being accessed.
Memory Data Register (MDR)Holds data or an instruction being transferred to or from main memory.
AccumulatorTemporarily stores data and intermediate results produced by the ALU.

Stages of the cycle

  1. Fetch: The PC contains the address of the next instruction. The CPU copies this address to the MAR. The control unit sends a memory-read signal, and main memory returns the instruction through the MDR. The instruction is then copied into the IR. The PC is updated to point to the next instruction (unless the instruction changes the sequence).
  2. Decode: The control unit examines the instruction in the IR. It identifies the operation to perform and determines whether additional data or memory addresses are required.
  3. Execute: The control unit directs the required data transfer. If an arithmetic or logical operation is needed, the ALU performs it. Operands may be held in registers, and the accumulator can store an intermediate or final result.
  4. Store: If required, the result is transferred from a CPU register to main memory. The MAR holds the destination address, while the MDR carries the data during the write operation.

CPU–memory interaction: The address is supplied through the MAR, while the MDR carries the instruction or data. The control unit coordinates read and write operations. After one instruction is completed, the CPU repeats the cycle for the next instruction.

3. Magnetic disks and magnetic tape in a university computer centre

Question. Demonstrate how magnetic disks (hard disk drives) and magnetic tape can be deployed in a university computer centre to store live student records and to take periodic backups of the same data.

A university computer centre can use hard disk drives (HDDs) for active student records and magnetic tape for periodic backups. The two technologies complement each other because they are suited to different storage needs.

Example deployment in a university computer centre
UseDevice and processResult
Live student recordsThe student information system stores its active database on HDD-based storage. The server reads and updates records such as enrolment, attendance, fee status and examination details.Staff and authorised students can retrieve and update current information through the university system.
Regular backupsAt scheduled intervals, backup software copies database backups and required files from disk storage to magnetic tape.A separate copy is available if the live database is damaged, deleted or affected by hardware failure.
Off-site protectionCompleted tapes are labelled, encrypted where supported, catalogued and moved to a secure off-site storage location.A fire, theft or other incident at the computer centre is less likely to destroy both the live data and its backup.
RecoveryIf the main storage fails, administrators restore the latest suitable backup from tape to replacement disk storage and apply any available later transaction logs.The student information system can be brought back online with minimal data loss, depending on backup frequency.

Practical safeguards

  • Schedule full and incremental backups according to the university's recovery requirements.
  • Keep multiple backup generations and at least one copy offline or off-site.
  • Restrict access to student records and encrypt backup media containing personal information.
  • Test restoration regularly; a backup is useful only if the data can be recovered.

Conclusion: HDDs provide convenient direct access for live records, while magnetic tape offers economical, removable storage for periodic backups and long-term retention.

4. Sequential access and direct access storage devices

Question. Distinguish between sequential access devices (e.g., magnetic tape) and direct access devices (e.g., magnetic disk, optical disk) in terms of data retrieval method, access time, typical applications and cost per unit of storage.

Storage devices can be classified by how data is located and retrieved. In sequential access, records are reached in sequence. In direct access, the device can move to a location and retrieve the required data without reading every preceding record.

Comparison of sequential and direct access storage
CriterionSequential accessDirect access
Example devicesMagnetic tape.Magnetic disk (HDD) and optical disk (CD, DVD or Blu-ray).
Data retrieval methodData is read in sequence. The tape must move past earlier data to reach a later record.The device locates the required block or sector directly, although mechanical movement or seek operations may still be involved.
Access timeUsually slower when a particular item must be found because preceding data may need to be passed.Generally faster for retrieving a particular file or block, especially on a well-organised disk.
Typical applicationsBackups, archival copies and large batches of data that are not accessed frequently.Operating systems, application files, databases, media and other data requiring regular retrieval.
Cost per unit of storageOften low for large-capacity tape storage, making it suitable for bulk backup and archives.Varies by medium; HDDs offer relatively economical online storage, while optical discs are useful for portable or distributable copies.

Conclusion: Sequential access is appropriate when data is stored or restored in large batches and low cost is important. Direct access is preferable when users and applications need to locate individual records quickly.

5. Comparison of RAM and ROM types

Question. Compare RAM (SRAM and DRAM) with ROM (PROM, EPROM and EEPROM) in terms of volatility, speed, cost, read/write capability and their respective roles during system boot-up and program execution.

RAM is temporary working memory used while programs run, whereas ROM is non-volatile memory commonly used to retain firmware. Their subtypes differ in speed, cost and the way their contents can be changed.

RAM: SRAM and DRAM

Comparison of RAM types
FeatureSRAMDRAM
VolatilityVolatile; loses data when power is removed.Volatile; loses data when power is removed.
SpeedVery fast; does not require periodic refresh.Slower than SRAM and requires periodic refreshing.
CostMore expensive per bit.Less expensive per bit and available in higher capacities.
Read/writeCan be read and written while powered.Can be read and written while powered.
Typical roleCommonly used for CPU cache.Commonly used as the computer's main system memory.

ROM: PROM, EPROM and EEPROM

Comparison of ROM types
TypeVolatility and rewritingTypical characteristic
PROMNon-volatile; programmed once by the user and cannot normally be erased.Useful when firmware or data needs to be permanently written after manufacture.
EPROMNon-volatile; erased using ultraviolet light and then reprogrammed.Can be reused, but erasing generally requires removing the chip from the circuit.
EEPROMNon-volatile; electrically erased and reprogrammed.Can be updated in-circuit, often in smaller sections.

Role during boot-up and program execution

  1. When the computer is switched on, firmware stored in non-volatile ROM or flash memory begins executing.
  2. The firmware performs basic hardware checks and initialises essential devices, then locates and starts the bootloader or operating system.
  3. The operating system and running programs are loaded into DRAM, where the CPU can access their instructions and data.
  4. SRAM cache keeps frequently needed information close to the CPU to reduce average memory access time.

Conclusion: RAM provides fast, temporary read/write working space, while ROM retains important instructions without power. Both are necessary for a computer to start and run programs.

6. Best medium for long-term archiving of institutional records

Question. Assess whether a magnetic tape library, a hard-disk-based mass storage array (RAID/NAS) or optical discs (CD/DVD/Blu-ray) is the most suitable medium for long-term archiving of institutional records, justifying your selection based on storage capacity, cost per GB, durability and data retrieval time.

For a large institution that must preserve records for many years, a magnetic tape library is generally the most suitable primary archival medium, provided that tapes are stored correctly and their contents are checked and migrated when necessary. A disk array or NAS is better suited to frequently accessed online data.

Assessment of long-term archival options
CriterionMagnetic tape libraryHDD array (RAID/NAS)Optical discs
Storage capacityHigh capacity per cartridge; libraries can hold many cartridges and scale by adding media.High capacity and convenient expansion by adding drives or arrays.Relatively low capacity per disc, so large archives require many discs.
Cost per GBUsually low for large-scale archival storage, although drives, robotics and management add initial cost.Generally higher for continuously available storage because drives, enclosures and redundancy are required.Media can be inexpensive, but large collections require handling, labelling and storage space.
DurabilityCan provide long service when stored in controlled conditions and handled correctly; periodic integrity checks and migration are still required.Drives have moving parts and can fail. RAID improves availability but is not a substitute for an independent backup.Can be durable when suitable archival-grade media is stored and handled correctly; discs may scratch or degrade.
Retrieval timeSlower; a cartridge may need to be mounted and the tape positioned.Fast online access, suitable for frequent searches and updates.Slower than online disks; discs may need to be located and loaded manually or by a jukebox.

Justification and recommended policy

  • Use tape for large volumes of records that must be retained but are accessed infrequently.
  • Keep an online disk/NAS copy for records that staff need to retrieve regularly.
  • Maintain more than one copy, with at least one copy offline and another at a separate location.
  • Use checksums and scheduled restore tests to detect corruption and confirm that files remain readable.
  • Maintain a catalogue of media, formats, retention dates and encryption keys, and plan periodic migration to supported hardware and file formats.

Conclusion: Tape offers a strong balance of capacity and cost for long-term institutional archives. It should be part of a managed archival strategy rather than the only copy of important records.

7. Factors affecting CPU performance

Question. Critique the statement that “increasing the CPU clock speed alone is the best way to improve computer performance”, by considering the roles of cache memory size, word length, number of cores and main memory capacity.

The statement is not completely correct. Increasing clock speed can improve performance, but it is not always the best solution because overall performance depends on several components working together. A faster CPU may still wait for data, be limited by software or generate too much heat.

How different factors influence CPU performance
FactorRole in performanceLimitation or consideration
Clock speedMeasures how many clock cycles the processor performs per second. A higher frequency can allow more cycles in a given time.More cycles do not automatically mean proportionally more completed instructions. Architecture, power limits, cooling and workload matter.
Cache memory sizeA larger or more effective cache can keep frequently used data and instructions near the CPU, reducing slower accesses to RAM.Cache is expensive and limited in size. Cache design and hit rate matter, not capacity alone.
Word lengthIndicates the number of bits a processor can handle as a unit and influences address space and the size of data it can process efficiently.A larger word length does not make every task faster; software and data types must benefit from it.
Number of coresMultiple cores can execute separate threads or tasks in parallel, improving multitasking and well-parallelised workloads.Software that cannot be divided into parallel work may gain little from extra cores.
Main memory capacityAdequate RAM allows active programs and data to remain in memory, reducing slow disk swapping.Adding RAM beyond what a workload needs may not noticeably improve CPU-bound tasks.

Overall assessment

For example, a processor with a high clock speed but insufficient RAM may slow down when several applications are open because the system must move data between RAM and storage. Similarly, a processor with multiple cores can handle parallel workloads efficiently even if its clock speed is lower.

The best improvement depends on identifying the actual bottleneck. A balanced system should have an appropriate CPU frequency, effective cache, suitable word length and core count, and enough main memory for its workload.

Conclusion: Clock speed is important, but it is only one performance factor. Balanced hardware and software optimisation provide better results than increasing frequency alone.

8. Balanced configuration for a 60-student college computer lab

Question. Design a balanced processor, memory and storage configuration for a computer lab of a college serving 60 students. Propose a coherent specification for the CPU, main memory (RAM/cache), primary storage and a backup/mass storage solution, justifying how the choices work together within a limited budget.

For a college lab serving 60 students, a practical approach is to provide 60 student computers with balanced mid-range specifications and centralised backup storage. The configuration should support programming, office applications, web browsing, online learning and introductory development tools without spending the budget on unnecessary high-end components.

Proposed configuration per student computer

Suggested specification for each of the 60 lab systems
ComponentProposed specificationReason
CPUModern 6-core, 64-bit processor with integrated graphics.Provides sufficient performance for multitasking, compiling beginner-level programs and everyday academic software without requiring a separate graphics card.
CacheProcessor's standard multi-level L1, L2 and L3 cache.Fast cache helps reduce repeated access to slower main memory. The lab can use the cache supplied with the selected processor rather than paying for a separate component.
RAM16 GB DDR4 or DDR5, depending on platform and price.Allows students to run an IDE, browser, documentation and other learning tools together. Memory should be upgradeable where possible.
Primary storage512 GB SSD per computer.Provides fast booting and application loading, with enough space for operating systems, tools and student work.
GraphicsIntegrated graphics.Suitable for normal programming and productivity tasks, avoiding the cost and power use of dedicated graphics cards.

Shared backup and mass storage

  • Central NAS: Use a network-attached storage system with multiple hard drives and RAID redundancy to store shared lab resources and centralised student-work backups.
  • External backup: Back up the NAS to external drives or magnetic tape on a schedule, keeping at least one copy offline or off-site.
  • Network: Connect the computers and NAS through a reliable gigabit Ethernet network for shared files and backup transfers.
  • Administration: Use standard software images, centralised updates and user accounts to simplify maintenance across all 60 systems.

How the configuration works together

The CPU executes student programs, using its cache for frequently accessed instructions and data. The 16 GB RAM holds active applications and files, while the SSD provides fast permanent storage for the operating system and local work. The NAS gives the lab a shared storage location, and a separate backup copy protects important work if the main storage is damaged.

Budget justification: A mid-range processor with integrated graphics, 16 GB RAM and a 512 GB SSD gives useful everyday performance without the expense of gaming-class hardware. Buying identical systems in bulk, choosing upgradeable components and using centralised backup and administration can reduce long-term purchase and maintenance costs.

Conclusion: This design balances processing power, memory and storage for 60 students. It prioritises responsive everyday use, manageable administration and reliable backups while keeping the configuration suitable for a limited college budget.
